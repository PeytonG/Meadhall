# CLAUDE.md — Meadhall

Guide for AI agents (and humans) working on this repository: what it is, how to work in it, what has been done and **why**, and what is still open. Keep it current: when you finish work or make a non-obvious decision, update the relevant section (especially "Status" and "Decisions").

## What this is

Meadhall is a self-hosted, Discord-style [Matrix](https://matrix.org) client (spaces = servers, rooms = channels) with a pixel-art look. It runs as a web app, an Electron desktop app (Windows, Linux, macOS) and an Android app (Capacitor).

- Repo: https://github.com/PeytonG/Meadhall (public, standalone, not a GitHub fork). Owner: PeytonG.
- Meadhall is a **fork of [Heorot](https://github.com/Vitosicz/Heorot)** by Vitosicz (remote `upstream`). The old GitHub fork `PeytonG/Heorot` still exists as remote `heorot-fork`; it is no longer used.
- License: **AGPL-3.0**, inherited from Heorot and Element and can't be changed. See "License rules".

## Commands

Run from the repo root unless noted. Package manager: **pnpm 10** (Node 22+).

```bash
pnpm install
pnpm typecheck                         # web app (tsc)
pnpm --dir apps/web test               # unit tests (Vitest, jsdom)
pnpm --dir apps/web test:smoke         # component smoke tests (VoiceRoom with faked LiveKit/MatrixRTC)
node scripts/test-synapse.mjs start    # Synapse v1.163 in Docker on :8008 (SYNAPSE_ROOM_VERSION=11|12 optional)
pnpm --dir apps/web test:integration   # integration tests against that Synapse
pnpm --dir apps/web test:e2e           # Playwright against the production build + that Synapse
node scripts/test-synapse.mjs stop
pnpm --dir apps/desktop run build:electron   # compile Electron main/preload
pnpm dev:web | pnpm dev:desktop
node scripts/generate-branding.mjs     # regenerate all icons/splashes/login art from branding/
CAPTURE_SCREENSHOTS=1 pnpm --dir apps/web exec playwright test screenshots   # refresh docs/screenshots
```

Run the relevant tests after every change. All of them passed at the last update of this file.

## Decisions and why

### Voice: MatrixRTC, Element Call compatible (verified against source, 2026-10-22)
Checked against Element Call main (v0.26.1, default **Compatibility** mode), lk-jwt-service v0.9.0 (Rust), and matrix-js-sdk 40.2.0 vs Element Call's pinned js-sdk commit:
- Transport discovery: `client._unstable_getRTCTransports()` → `.well-known` `org.matrix.msc4143.rtc_foci` → config `default_server_config` rtc_foci → config `livekit_service_url`. Cached per client (failures for 60s). Only `https:` (or http localhost) service URLs.
- Token: `POST {livekit_service_url}/sfu/get` `{room, openid_token, device_id}` → `{url, jwt}`. This is exactly what Element Call publishers do, because only `/sfu/get` assigns the legacy identity `@user:server:DEVICE`. `/get_token` and the homeserver-proxied MSC4195 endpoint assign **hashed** identities. Both endpoints map to the same LiveKit room (`sha256(json([room, "m.call#ROOM"]))`). `/sfu/get` is marked deprecated in lk-jwt-service but still served.
- Join: `joinMatrixRtcSession()` in `core/voice/matrixRtc.ts` (shared by VoiceRoom and the tests) → `joinRTCSession({userId, deviceId, memberId: "user:device"}, [], {…transport, livekit_alias: roomId}, {callIntent: "audio", manageMediaKeys: encrypted, useExperimentalToDeviceTransport: true})`. To-device keys are **required**: Element Call only sends media keys via to-device. Result: a legacy session state event with `focus_active: {livekit, multi_sfu}`.
- E2EE: `MatrixRtcKeyProvider` (BaseKeyProvider, ratchetWindowSize 10, keyringSize 256) imports keys with livekit's `createKeyMaterialFromBuffer` (copying exactly the Uint8Array view's bytes). Room option `e2ee` (not `encryption`, which also encrypts data channels, which Element Call doesn't), worker via `livekit-client/e2ee-worker?worker&inline`, `setE2EEEnabled(true)` after connect.
- Key event format is compatible both ways (Element Call still sends the deprecated `keys`/`member.id`). Our SDK matches received keys to memberships by user + device.
- Participants: resolved via `rtcBackendIdentity → userId` from session memberships, then by parsing `@user:server:DEVICE`. Remote Element Call clients on other homeservers may join our SFU as **subscribers** with hashed identities; those are hidden (unresolvable + no published tracks).
- RoomList voice presence comes from `session.memberships` when MatrixRTC is available; otherwise the relay is polled.
- **heorot-voice-relay** stays as a fallback when no transport is discovered (relay calls aren't visible to Element users).

### Voice channels must let members send call memberships (bug found by integration tests)
`org.matrix.msc3401.call.member` is a *state* event; members (PL 0) can't send it at `state_default` 50. Previously only moderators could really join calls. Now:
- New voice channels (create dialog + Discord import) get `events["org.matrix.msc3401.call.member"] = channel level` via `allowCallMemberships()`, which **edits the real power levels after creation**. Do NOT pass `events` in `power_level_content_override`: Synapse merges it shallowly and replaces the default `events` map, and those defaults differ by room version (v12 has tombstone 150).
- Joining checks `canJoinCalls()` first and explains instead of half-joining. Admins of older channels see "Allow members to join calls" in the voice panel (`allowMembersToJoinCalls`). A `MembershipManagerError` leaves the call with an error.

### Discord import: never put `m.room.power_levels` in `initial_state`
It replaces the server's defaults, so the creator loses rights, and on room versions below 12 `createRoom` fails (`M_FORBIDDEN user_level (0) < send_level (50)`). Use `power_level_content_override` for scalars like `events_default`. In room v12 creators have unlimited power (`powerLevel === Infinity` in js-sdk).

### Desktop
- Permissions: deny all except `media`, `notifications`, `clipboard-sanitized-write` (copy buttons/recovery keys), `fullscreen` (screen-share stage), and only for the app origin. `getDisplayMedia` goes through `media` and then the display media handler.
- Tray + close-to-tray (the existing "close minimizes" setting now hides to tray; falls back to minimize without a tray; macOS unchanged). Relaunching focuses the running app (single-instance lock).
- Open at login: Electron login items (Windows/macOS), XDG autostart `~/.config/autostart/meadhall.desktop` on Linux (uses `$APPIMAGE`). Starts hidden (`--hidden`).
- Auto-update: electron-updater from GitHub Releases of PeytonG/Meadhall. Installs on quit, or "Restart to update" banner (silent install, since the NSIS installer is assisted, `oneClick: false`). The quit flag is only set when an install proceeds. `HEOROT_DISABLE_AUTO_UPDATE=1` disables it. Unsigned macOS can't auto-update (harmless error).
- App ID `io.github.peytong.meadhall` (installs alongside upstream Heorot, separate profile).

### Branding and theme
- Name "Meadhall" (Heorot is *the* mead-hall in Beowulf). `config.brand` drives the login heading, page title, device names ("Meadhall Web/Desktop"); the default is in `core/config/branding.ts`.
- Artwork from the owner: `branding/meadhall-icon.jpg` (horn) and `branding/meadhall-hall.jpg` (login backdrop). `scripts/generate-branding.mjs` (sharp) cuts the icon out of its white background by flood-filling from the edges and writes every icon, splash and webp. Re-run it after artwork changes; outputs are committed.
- Theme: **pixel art everywhere** (`ui/styles/pixel.css`, imported last). Square corners, stepped borders, bevelled action buttons (not text-like buttons), Pixelify Sans + Silkscreen bundled via @fontsource (CSP only allows local fonts).
- Accent: default **bright purple `#a64dff`**, user-selectable with the **pixel color wheel** (`ui/theme/PixelColorWheel.tsx`, Appearance settings). `accentTokens()` derives `--primary/--accent/--accent-soft/--primary-rgb/--on-primary`, shifting the shade until it has 3:1 contrast with the background and picking button text for 4.5:1. CSS defaults in App.css/settings/styles.css must match `accentTokens(DEFAULT_ACCENT_COLOR, theme)`. The encrypted-channel badge stays **green** on purpose (security signal).
- Saved appearance is applied at startup (App.tsx), so the sign-in screen uses it.

### Testing
- Integration tests run against a real Synapse on **room versions 11 and 12** (CI matrix). They cover the import, the MatrixRTC membership as Element Call reads it, member call permissions, and real Olm to-device media key exchange between two crypto clients.
- E2E: Playwright against the production build served by `e2e/serve.mjs`, which writes `dist/config.127.0.0.1.json` (hostname config wins over config.json, so nobody's config is touched). Setup through the client-server API; test channels are unencrypted because the API helpers can't encrypt.
- Smoke tests fake livekit-client and MatrixRTC but use the real adapter helpers.

## Gotchas (learned the hard way)

- VS Code's extension host sets `ELECTRON_RUN_AS_NODE=1`; unset it before launching Electron from an agent shell or `require("electron")` returns a path string.
- PowerShell: `"$nlimport"` is one variable. Bash on Windows (Git Bash) mangles a leading `//` in arguments (an SPDX header became `/ SPDX`). Prefer the Edit tool for source edits. Files use CRLF in the working tree.
- Synapse's Docker `generate` hands the data dir to uid 991 on Linux; the test script mounts overrides separately and cleans the dir from inside a container.
- After a page reload, a fresh test account is offered "Set up secure backup" again; use `waitForAppShell()` in E2E.
- `.login-card button` out-ranks `.login-mode-button` in CSS specificity (fixed in pixel.css).
- Typecheck needs tsconfig `paths` for every `matrix-js-sdk/src/*` deep import (map to `lib/*.d.ts`), otherwise tsc compiles the SDK's sources and fails.

## Open issues / future work

- **Multi-SFU**: we only connect to our own SFU. Element users on another homeserver publishing to a different SFU are not heard (they can hear us). Element Call subscribes to every member's SFU; implementing that means one LiveKit connection per remote transport (subscriber role via `/get_token`).
- **Matrix 2.0 mode**: Element Call's opt-in `Matrix_2_0` mode uses sticky `m.rtc.member` events and hashed identities. js-sdk 40.2 hashes `user|device|member` while lk-jwt-service hashes JSON `["user","device","member"]`. Upgrading matrix-js-sdk (44+) should fix this before Element Call makes that mode the default.
- Homeservers that advertise only the MSC4195 `url` transport (no `livekit_service_url`) aren't supported yet (we fall back to the relay).
- Android release signing: set repo secrets (see release workflow) or APKs are debug-signed, and users can't update between differently-signed builds.
- macOS builds are unsigned (no auto-update); there is no iOS app.
- Push notifications are not implemented.
